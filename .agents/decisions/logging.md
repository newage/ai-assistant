# Decision Log: Structured JSON logging

## Problem
`ai-service` and `mcp-server` only emit unstructured, error-only output (`log.exception`), and a single user request that crosses both services (chat → agent → MCP → MySQL) has no shared identifier. Investigating an incident per request is guesswork by timestamp, and there is no controlled way to turn detailed (debug) logging on or off. If nothing is done, debugging stays manual correlation of two unrelated streams.

## Given
- `ai-service` uses stdlib `logging` with no configuration or format; one uvicorn process — verified: `ai-service/app/main.py`, `tools.py`, `Dockerfile`.
- `mcp-server` is Swoole with `MCP_WORKERS=2`; no logger and no `monolog` dependency — verified: `mcp-server/server.php`, `composer.json`.
- `ai-service` calls MCP via `MultiServerMCPClient` with a static `url`/`transport`; tools are loaded on every `reply()` — verified: `ai-service/app/tools.py`, `agent.py`.
- Settings come from `.env` via pydantic (`settings.py`) in Python and `getenv` in PHP; no shared volume for logs in compose — verified: `settings.py`, `server.php`, `docker-compose.yml`.
- The chat bot is an external client; all its traffic goes only through `ai-service` — `CLAUDE.md`.
- Log levels: critical, error, warning, info, debug (`notice` dropped as unnecessary) — user's words.
- Target line format: `{"priority","service","short_message","x-request-id","extra","timestamp"}` — user's example in `.agents/propose/logging.md`.
- `LOG_ID` (developer id) and `ENVIRONMENT` come from env; many developers share `ENVIRONMENT=local`, so `LOG_ID` distinguishes them for global logging — user's words.
- Debug level is on only in dev and switchable from env; additionally enabled per request by header `X-Debugging: true` sent by the external client — user's words.
- `x-request-id` is accepted from the incoming HTTP request or generated by `ai-service`, passed to the PHP service as an HTTP header, and added to all of its logs for that request — user's words.

## Solution Concept
**Chosen:** B — both services write JSON lines to stdout; Docker's logging driver stores and rotates them (`max-size: 1m`, `max-file: 2`).
**Whose:** generated in the funnel (the developer's initial idea was A, files in a shared volume)
**Why:** no shared volume, no file handlers and no custom rotation in two languages; rotation is delegated to Docker.
**Rejected:**
- A. Files in a shared volume `/data/logs` — Monolog's `RotatingFileHandler` rotates by date only (no size, no weekly), and two Swoole workers plus a second service writing to the same file need a custom handler.
- C. Sidecar collector writing files — an extra container and config for a demo.
**Consequences accepted by the developer (the original brief changes):**
- Dropped: `/data/logs`, the volume, file names `/{logId}_{ENV}.log`, `RotatingFileHandler`, date-based rotation (dev weekly / prod daily).
- `LOG_ID` and `ENVIRONMENT` become fields in every JSON line.
- Rotation is by size only (the original "1 MB + 1 old copy") via Docker.

## Vector
```
external client --POST /chat--> ai-service
  [X-Request-ID?]                 middleware: id = header or uuid4 (returned in response header)
  [X-Debugging: true?]            contextvar: request_id, debug
                                  JSON -> stdout
                                        |
                                  Assistant.reply()
                                        | MCP client built per request with headers
                                        v   X-Request-ID, X-Debugging
                                  mcp-server (Swoole)
                                        | per-request Monolog logger, id in every line
                                        | JSON -> stdout
                                        v
                                      mysql
Docker logging driver: json-file, max-size 1m, max-file 2
```
- `ai-service` takes `X-Request-ID` from the request or generates it, keeps it in a contextvar, a logging filter adds it to every record, and it is returned in the response header.
- Headers go to MCP via a client created per request (`McpTools.load()` already runs on every `reply()`).
- `mcp-server` creates a Monolog logger per request that takes the id from the header (`-` if absent).
- `X-Debugging: true` raises the level to debug for that request only; the business logic, DB schema and `POST /chat` contract are untouched apart from the new response header.

## Details
### Debug switching
**Decision:** effective level is debug if `X-Debugging: true` is present (any environment); otherwise debug iff `ENVIRONMENT != prod`; otherwise info.
**Why:** developer's rule: no header and not prod means debug.
**Alternative:** a separate `LOG_DEBUG` env flag — not needed, derived from `ENVIRONMENT`.

### What is logged
**Decision:** info logs metadata only (request start/end, tool name, duration, status); debug additionally logs full user messages, tool arguments and results, truncated to ~500 chars.
**Why:** debug is switched on deliberately, so info stays free of user data.
**Alternative:** metadata only even in debug (blind debugging); content at info (user data in every request).

### Scope of JSON
**Decision:** all Python output is JSON (app logs and uvicorn access/error logs with `x-request-id`); Swoole's own system messages stay plain text.
**Why:** developer: leave Swoole system messages as text (rejected the FIFO wrapper and supervisor); uvicorn is configured from Python at low cost.
**Alternative:** wrap Swoole output in JSON via FIFO/supervisor — rejected as extra infrastructure.

## Open questions
- None.

## Assumptions
- JSON field names: `log_id`, `environment` added next to the fields from the brief's example (`priority`, `service`, `short_message`, `x-request-id`, `extra`, `timestamp`) — not blocking.
- An incoming `X-Request-ID` is accepted only if it matches `[A-Za-z0-9._-]{1,64}`, otherwise a new one is generated (prevents log injection) — not blocking.
- Only the value `true` of `X-Debugging` has an effect; `false` or other values are ignored (no way to silence debug in dev per request) — not blocking.
- `mcp-server` receives `LOG_ID`, `ENVIRONMENT` and the log level from env via compose, same as `ai-service`.
- Library choices stay as in the brief: `monolog` for PHP, stdlib `logging` for Python.
